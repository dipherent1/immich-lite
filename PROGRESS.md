## ✅ Phase 1 — Accounts & Auth

**Goal:** Users can register and log in.
**Status:** Complete. All stop conditions verified.

### What was done

- **`models/user.py`** — `User` SQLModel table: `id` (UUID PK), `email` (unique), `hashed_password`, `display_name`, `created_at`.
  - Registered in `models/__init__.py` so Alembic autogenerate sees it.
- **`core/security.py`** — password hashing via `pwdlib[bcrypt]` (`BcryptHasher` explicitly, not `PasswordHash.recommended()` which defaults to argon2), plus JWT encode/decode via `PyJWT` (HS256, sub/iat/exp claims).
- **`repositories/user_repository.py`** — `UserRepository` class (DB session injected) owns all `users` table access: `get_by_id`, `get_by_email`, `create`.
- **`services/user_service.py`** — `UserService` class owns the business logic and raises `HTTPException` for errors: `register` (409 dupe), `authenticate` (401), `get_by_id`. No DB or raw SQL in the service.
- **`api/deps.py`** — `get_user_repository` / `get_user_service` dependency factories, plus `get_current_user`: `OAuth2PasswordBearer` → decode token → load user via the service/repo; raises 401 with `WWW-Authenticate` on any failure.
- **`api/v1/endpoints/auth.py`** — thin router: `POST /api/v1/auth/register` (201/409), `POST /api/v1/auth/login` (200/401); each delegates to `UserService` via `Depends(get_user_service)`.
- **`api/v1/endpoints/users.py`** — thin: `GET /api/v1/users/me` (protected, returns `current_user`).
- **`schemas/`** — `auth.py` (`RegisterRequest`, `LoginRequest`, `TokenResponse`) and `user.py` (`UserResponse`); `EmailStr` requires `email-validator`.
- **`api/v1/api.py`** — now wires in `auth` and `users` routers.
- **Layering**: routers → `UserService` → `UserRepository` → models. Routers hold no DB logic; all SQLAlchemy lives in the repository.
- **Settings** — added `jwt_secret`, `jwt_algorithm`, `jwt_expires_minutes` to `core/config.py`. `jwt_secret` defaults to `None` ("not configured") and is loaded via `load_dotenv()` from the project-root `.env` (absolute path, so it works regardless of the CWD uvicorn is launched from); `jwt_algorithm` (`HS256`) and `jwt_expires_minutes` (`60*24*7`) keep code defaults. A dev copy lives in `.env` (gitignored); `docker-compose.yml` passes `JWT_SECRET=${JWT_SECRET:-change-me-in-production}` into the app container since `.env` is excluded from the Docker build.
- **`requirements.txt`** — added `pwdlib[bcrypt]`, `PyJWT`, `email-validator`.
- **`migrations/versions/1ab6d3380011_create_users.py`** — generated by autogenerate, reviewed, then applied.
  - NOTE: switched the generated `sqlmodel.AutoString()` columns to `sa.String()` (the autogenerated file referenced `sqlmodel` without importing it — a known SQLModel/Alembic quirk).

### Stop-condition verification

- ✅ `alembic upgrade head` runs cleanly against the `users` table.
- ✅ `alembic downgrade -1` runs cleanly (drops `users`).
- ✅ Can register (`POST /auth/register` → 201), duplicate email → 409.
- ✅ Can log in (`POST /auth/login` → 200 bearer token), wrong password → 401.
- ✅ Protected `GET /users/me` returns the user with a valid token (200); 401 without a token or with a bad token.
- ✅ Password hashes (bcrypt) never returned from any endpoint — `UserResponse` exposes only `id`, `email`, `display_name`, `created_at`.

### Notes / environment quirks

- The shared `get_db` dependency yields a **plain SQLAlchemy `Session`** (not `sqlmodel.Session`), so `db.exec()` is unavailable — endpoints use `db.scalars(select(...))` / `db.get(...)` instead.

### Notes / environment quirks

- On this Windows host, the OS reserves TCP port ranges (e.g. `6267–6366`, `7906–8005`) that block binding of the standard ports: `6333`/`6334` (Qdrant) and `8000` (API) all fail with WinError 10013 even in plain Python (Docker isn't the cause). The compose file maps to free host ports instead: Qdrant `8090`/`8100`, API `8080`, Postgres `5433`. The Qdrant container also remains reachable over the Docker network. `docker compose up -d` now succeeds on this machine.
- The native Windows Postgres owns host port `5432`; this project's Postgres uses host port `5433`.
