## ✅ Phase 3 — Events

**Goal:** Users can create an event with a shareable link; opening that link while active marks you an attendee.
**Status:** Complete. All stop conditions verified against the rebuilt Docker container.

### What was done

- **`models/event.py`** — `Event` SQLModel table: `id` (UUID PK), `owner_id` (FK → `users.id`, indexed), `name`, `join_token` (random slug, unique + indexed), `starts_at`, `expires_at` (nullable), `created_at`.
- **`models/event_attendee.py`** — `EventAttendee` with composite primary key `(event_id, user_id)` (no surrogate id) plus `joined_at`.
- **`repositories/event_repository.py`** — `EventRepository` (injected session) owns all `events` + `event_attendees` SQLAlchemy access: `create_event`, `get_by_id`, `get_by_token`, `is_attendee`, `add_attendee` (idempotent upsert — skips if already present, so the composite PK never dupes), `attendee_count`.
- **`services/event_service.py`** — `EventService` owns the business rules and raises `HTTPException`:
  - `create` — refuses with 400 if the owner has no face profile (Phase 2 prerequisite); validates the time window (422 if `expires_at <= starts_at`); generates the `join_token` via `secrets.token_urlsafe`; the owner is auto-added as the first attendee.
  - `join` — looks up by token (404 unknown), checks the active rule (410 if inactive), idempotently adds the attendee.
  - `get_by_id` — returns the event + attendee count, but only to the owner or an attendee (403 otherwise).
- **`schemas/event.py`** — `EventCreate` (name, `starts_at` default now, optional `expires_at`), `EventResponse` (`active` computed), `EventDetailResponse` (+ `attendee_count`), `EventJoinResponse` (`event` + `joined`).
- **`api/v1/endpoints/events.py`** — thin router:
  - `POST /events` (201) — create (owner must already be scanned).
  - `GET /events` (200) — list the current user's own/attended events, newest first.
  - `GET /events/search?q=` (200) — partial, case-insensitive name search across all events (`/search` is registered before `/{event_id}` so it isn't captured as an id). **Returns `EventPublicResponse`, which deliberately omits `join_token` (and image refs once photos ship) so a searcher can discover an event but not join it** — a join-by-request flow comes later.
  - `GET /events/join/{join_token}` (200/410) — authenticated; joins as attendee if active.
  - `GET /events/{id}` (200/403/404) — details + attendee count for members only.
- **`api/deps.py`** — new factories: `get_event_repository`, `get_event_service` (reuses `get_profile_service` for the face-profile prerequisite).
- **`models/__init__.py` / `schemas/__init__.py` / `api/v1/api.py`** — registered the new models, schemas, and wired in the `events` router.
- **`migrations/versions/807a2c7966ca_create_events_and_attendees.py`** — autogenerated, reviewed, `sa.String()` fix applied (matches the Phase 1 convention), then applied. Establishes FKs and the composite PK.
- **Frontend** — `frontend/src/components/EventsView.tsx` (events hub on the dashboard):
  - **Create** — name + optional close time → shows the shareable join link with a copy button.
  - **Your events** — list of owned/attended events with open/closed badge and copyable join link.
  - **Search** — public name search; results show only public fields (no join token by design), with a "requesting to join is coming soon" note.
  - **Join** — paste a shared join link/token → joins if active.
  - `lib/api.ts` added `createEvent` / `listMyEvents` / `searchEvents` / `joinEvent` (all authenticated) plus the `Event*` types.
  - **`/join/[token]`** — shareable join landing page: share links are `origin/join/<token>`. Unauthenticated visitors get "log in / register" links that return here via `?next=`; authenticated visitors auto-join on load and are redirected to the event preview. `LoginForm` now honors `?next=` so a logged-out user is returned to their join link after logging in. Auth state is read via `useSyncExternalStore` so the server/prerendered HTML and the client's first render agree (server snapshot = null) — avoids a hydration mismatch that occurred when initializing from `window` in state.
  - **`/events/[id]`** — event preview page (member-only, hits `GET /events/{id}` → `EventDetailResponse`): shows name, open/closed badge, created/starts/closes times, attendee count, and the copyable invite link. Entry points: clicking an event name in "Your events", and after creating or joining an event (create/join now redirect here). `lib/api.ts` added `getEvent(id)`.

### Explicit "active" rule (decided)

Time window (simplest option from PHASES.md): an event is joinable when `starts_at <= now` and `expires_at` is null (left open) or `now <= expires_at`. No owner `is_open` toggle this phase. Joining an inactive event → **410 Gone**.

## ✅ Phase 5 — Matching & Delivery

**Goal:** a processed event photo's detected faces are matched against the event's attendee face profiles (`user_profiles`), one `PhotoMatch` row is written per (photo, user) keeping the best similarity, and matched photos are delivered to users via an authenticated `GET /api/v1/matches/me` feed. Push/email are out of scope — the feed is the delivery.
**Status:** Complete. All stop conditions verified against the rebuilt Docker stack.

### What was done

- **`models/photo_match.py`** — `PhotoMatch` (SQLModel): `id` (UUID PK), `photo_id` (FK → `photos.id`), `user_id` (FK → `users.id`), `similarity` (double), `bbox` (stored as a JSON string with a `bbox_dict` property), `created_at`. Unique constraint `(photo_id, user_id)` guarantees one row per pair → `upsert_best` keeps the highest similarity instead of duplicating. Registered in `models/__init__.py`.
- **Migration `migrations/versions/0004_create_photo_matches.py`** — Alembic creates `photo_matches` (+ `uq_photo_matches_photo_user`, FKs, indexes). Applies, rolls back to `0003`, and re-applies cleanly.
- **`core/vector_db.py`**:
  - `QdrantProfileRepository.query_similar_restricted(query, user_ids, *, threshold, limit)` — searches `user_profiles` **only among the given attendee ids** (payload filter `user_id in user_ids` on `score_threshold`) — matching never scans the whole profiles collection.
  - `EventFaceRepository.get_faces_for_photo(photo_id)` — reads a photo's per-face vectors back from `event_faces` (scroll filtered on `photo_id` payload).
- **`repositories/event_repository.py`** — `list_attendee_ids(event_id)` returns the attendee user ids for an event.
- **`repositories/photo_match_repository.py`** — `upsert_best(...)` (see model) and `list_feed_for_user(user_id, offset, limit)` — one query, joins `PhotoMatch → Photo → Event`, newest first, `limit+1` for `has_more`, returns `(match, event)` tuples.
- **`services/matching_service.py`** — `MatchingService`:
  - `match_photo(photo)` — scoped matching: `list_attendee_ids` → `get_faces_for_photo` → per face `query_similar_restricted(above threshold)` → `upsert_best` each hit. Returns the number of rows written. Kept fully independently callable/testable.

### Bug fix — worker Redis connection timeout killed matching (invisible bug)

**Symptom:** user scans their face and uploads it to an event but it "doesn't match"; nothing new appears in `/matches/me`.

**Diagnosis (dumped live Qdrant + workers):**
- `user_profiles` and `event_faces` vectors were **correct** — the user's profile (user `6080862f-…`) and their uploaded event face had *identical* vectors.
- Driving the exact matching path (`list_attendee_ids` → `query_similar_restricted`) returned `0.99999994` — the **backend matching logic was not broken**.
- Worker logs showed the real defect: recurring `[ERROR] rq.worker: Worker …: Redis connection timeout, quitting...` every ~6.5 min. RQ 2.12's `worker.work()` **exits when the long-idle Redis connection times out**, killing the whole process. While the worker was down, newly-uploaded photos sat unprocessed, so they were never matched.
- The worker container kept auto-restarting (`restart: unless-stopped`), which masked it as a random crash instead of a code bug.

**Fix (`src/app/workers/photo_worker.py` `main()`):**
- Build the Redis connection with `socket_keepalive=True`, `socket_timeout=None`, `socket_connect_timeout=10`, `retry_on_timeout=True`.
- Wrap `worker.work()` in an outer `while True` loop that logs and reconnects after 3s on any `RedisConnectionError`/`RedisTimeoutError` (or when `work()` returns), so a transient timeout can **never** permanently kill the worker.

**Verified end-to-end:** rebuilt the worker, `/matches/me` returned the first entry as the user's brand-new upload (photo `acc1c43e`…) at the top with `similarity 0.99999994`.
